# No real names in git or on GitHub

**The rule:** nothing that names a real person, customer, site, domain, server, IP, Slack channel, webhook or service account goes into this repository: not in code, tests, fixtures, docs, screenshots, commit messages, branch and tag names, PR or issue titles and texts, comments or releases. Use the reserved examples (`shop.example`, `example.com`, `puls.example.com`, `203.0.113.10`, "a customer", "a production install") instead. Write a decision with its reason, not who made it: git and GitHub already show who.

**Why:** the repository is public, and git keeps everything: a name in an old commit message or a PR text is as public as one in the code, and taking it out later means rewriting history. Editing a PR text does not help either: GitHub keeps its earlier versions. It slips in most easily in text written while looking at production data ("the dashboard showed ... for <real site>"): describe the case with example names instead. Puls was public for months with only a sentence in CLAUDE.md, and the production domain still ended up in docs, a skill, the CLI's example URL and a commit message; a rule alone does not hold, hence the hooks (the same as Vaka's).

**How it is enforced** (so it does not depend on remembering):

- `.private/real-names.txt` (gitignored) lists the real names: the tracked sites, customers, servers, IPs and services. Keep it up to date when sites or servers change. The hooks match text, so an international domain goes in both spellings (`xn--...` and as written), and a removed site stays in the list (old notes still name it). Names and text are compared in one Unicode form (NFC, with Perl), since "ö" written as "o" plus a combining diaeresis (NFD, common on macOS) would otherwise slip through.
- `scripts/hooks/pre-commit` stops a commit that adds a line with one of them; `scripts/hooks/commit-msg` stops a commit message with one; `scripts/hooks/pre-push` checks what a push sends to GitHub: branch and tag names, tag messages, and the messages and added lines of every commit not yet on the remote (so a name added to the list later still stops the push), then runs the tests. All use `scripts/hooks/real-names`, and `composer install` turns them on (`core.hooksPath`).
- `.claude/hooks/no-real-names.sh` (PreToolUse) stops a `gh` command that sends text to GitHub (`pr` and `issue` create/edit/comment/review/merge/close, `release` and `repo` create/edit, `gist`, and every `gh api` call) when the text, inline or in a file (`--body-file`, `-F`, `--notes-file`, `--input`, `-F field=@file`), contains one. A merge made on GitHub writes its commit there, past the git hooks, so `gh pr merge --subject/--body` is checked here. Local paths in the command are not checked (they never reach GitHub); give files as paths without shell variables, so the hook can read them. It reads the whole command line, so a name in a command next to `gh` stops it too: run `gh` on its own. Reading only the `gh` part of a line was considered and declined: it saves a rare false alarm, and a mistake in parsing the shell would let text through instead of stopping it.
- Without `.private/real-names.txt` (a fresh clone, a contributor) nothing is checked: the list is what is private.
- Handoffs name customers and sites, so they live in `.claude/handoffs/`, which is gitignored.

When a hook stops you, rewrite the text with example names. Never bypass it with `--no-verify`, and never weaken the list to get a commit through.
